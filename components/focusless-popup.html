为什么值得借鉴

  1. 灵动岛窗口带 WS_EX_NOACTIVATE、不抢焦点，Qt/QMenu 自带的「点外面关闭」靠失焦触发——在这里永远不会发生，关闭条件必须自己造（system.py:26 注释原话）。
  2. 不装全局鼠标钩子，只用 GetAsyncKeyState 每 25ms 轮询三枚鼠标键：十行代码，没有钩子泄漏风险，也钓不到别的进程的事件。
  3. armed 状态机专治「打开菜单的那次点击」误伤：先等那次按键松开才武装（system.py:41 注释「先等打开菜单的那次按键松开」），否则菜单刚弹出就被同一击关掉。
  4. 关闭判定只看「按下 ∧ 光标在所有可见菜单之外」，与焦点、z-order、谁在前台完全无关；多菜单并存时任一菜单包含光标就不关。
  5. 输入框要键盘就必须抢焦点，于是用 locks["focus"] 锁住自动收起；前台窗口一变立即释放，否则灵动岛「会一直保持展开」（island.py:1038 注释）。
  6. locks 是一个集合，pin/focus/menu/lookup 任一在位就不收起（island.py:1091）——弹层生命周期与展开生命周期共用同一把锁，机制解耦、状态不打架。

实现要点

  1. t.setInterval(25)（system.py:31）；aboutToShow 时 armed=False 并启动，aboutToHide 停表（:51-52）——菜单一关轮询立刻归零。
  2. down() = GetAsyncKeyState(k) & 0x8000，k ∈ {0x01 左键, 0x02 右键, 0x04 中键}（system.py:34）；lookup 弹窗只查 {0x01,0x02} 两键（lookup.py:117）。
  3. tick 三分支：不可见→停表（:37-39）；未武装→armed = not down()（:40-42）；武装且按下→光标不在任何可见 QMenu 几何内→close + 停表（:43-49）。
  4. request_focus()（island.py:1241）四步：存 _prev_fg（:1245）→ 摘掉 WS_EX_NOACTIVATE（:1247）→ AttachThreadInput 借前台线程 → locks.add("focus")（:1256）。
  5. release_focus()（:1258）三步：恢复 WS_EX_NOACTIVATE（:1264）→ clearFocus() → SetForegroundWindow(_prev_fg) 把前台还回去（:1269）。
  6. _poll_hover()（:1037）每帧先查 "focus" in locks and GetForegroundWindow() != hwnd → 立即释放（:1039-1041）；展开态下 locks 非空则直接 return 不计时收起（:1091）。
